# 商品上下架自动化

基于 Codex 技能、飞书多维表格和天猫（千牛）的商品发布与运营管理流程。技能名为 `product-listing`，由 Agent 按任务读取规则、操作已授权工具，并将平台结果回写飞书。

这是供 Agent 执行的技能说明与流程规范，不是可以独立运行的一键上架程序。

## 当前能力

| 能力 | 支持情况 |
| --- | --- |
| 飞书商品、SKU、尺码与素材管理 | 支持，按关联记录组织数据 |
| 上架链接批量创建与查重 | 支持，重名跳过、重跑去重 |
| 天猫发布预检与提交 | 支持，按当前店铺和类目表单执行 |
| 立即上架 / 放入仓库 | 支持，遵循链接配置及用户授权 |
| 提交后状态核实与回写 | 支持，区分预检中、已入仓、出售中及平台拒绝 |
| 飞书运营看板 | 支持，直接统计源表，区分链接数与异常记录数 |
| 商品下架 | 尚未提供专门流程，不能视为已支持 |
| 其他电商平台 | 可维护飞书资料，平台发布流程尚未接入 |

## 工作方式

1. 从飞书读取目标链接，以及关联商品、规格、尺码、价格、库存和素材。
2. 核对店铺、类目、已有商品与必填资料，按授权补齐可确定的配置。
3. 连续提交符合条件的链接，保存即时回执和商品 ID，回写后继续下一条。
4. 将最终状态查询放入独立核实队列，按平台处理时间集中查询。具备隔离查询环境时，可由专门子智能体协助核实，主 Agent 统一回写。
5. 汇总提交、入仓、在售、拒绝、暂停与待核实结果，说明真实失败原因和下一步。

平台预检等待不阻塞后续提交。普通提示或可选资料疑点不自动升级为阻塞；单条失败后继续其他可处理链接。提交结果不明时先核实，避免重复发布。既有商品不计作本次发布成果。

## 使用前准备

- 可以加载本地 `SKILL.md` 的 Codex 环境。
- 已连接且具有目标 Base 读写权限的飞书工具，或已配置的 `lark-cli`。
- 已安装的 `ego-browser` 技能及运行环境，用于操作已登录、具备目标店铺权限的千牛页面。
- 目标飞书 Base 链接及商品实际资料。仓库不包含店铺账号、凭据、商品素材或业务数据。

## 安装

将仓库中的 `skills/product-listing` 整个目录复制到 Codex 的技能目录，例如 Windows 的 `%USERPROFILE%\.codex\skills\product-listing`。如已安装同名技能，先比较已有内容，保留所需的本地配置，再合并更新。

本仓库版本通过用户请求或当前会话确定目标 Base，不绑定任何实际飞书地址。安装后，在使用请求中提供目标 Base 链接。

## 示例请求

```text
$product-listing 检查这个飞书 Base 中哪些待发布链接可以提交：<Base 链接>
```

```text
$product-listing 发布已确认的待发布链接，使用表里的价格和库存，发布方式为放入仓库。
```

```text
$product-listing 核实已提交商品的入仓或在售状态，并回写飞书。
```

```text
$product-listing 优化运营看板，并检查源数据已修改但指标没有变化的原因。
```

## 数据结构与看板

飞书管理表由八张表组成：商品档案、SKU、尺码表、商品素材、上架链接、链接 SKU、链接素材、上架失败。

- 一款商品维护一个统一售价；链接规格保存投放库存和库存来源。
- 运费承担方式、运费模板、发货时间、发货地分别记录。运费模板按当前平台表单要求判断，不填虚构模板。
- 发布进度取自「上架链接 → 发布状态」，异常待办取自「上架失败 → 处理状态」。
- 看板区分业务链接总数、待提交、待核实、已入仓、已上架和受阻链接；验收草稿排除在业务统计之外。
- 看板不会自行查询天猫，平台状态须经核实后回写；修改商品价格或备注不会直接改变发布进度。

## 仓库结构

```text
skills/product-listing/
├── SKILL.md                 技能入口与任务路由
└── references/
    ├── feishu.md            数据结构、资料维护与看板规则
    ├── setup.md             初始化表、关联和工作视图
    └── tmall.md             预检、提交、核实、异常处理与汇报
```

本仓库按私有项目管理。工具调用方式以本机当前工具文档为准，平台操作以实际页面和回执为准。发布前需明确操作范围；维护飞书资料不等于授权提交平台。
