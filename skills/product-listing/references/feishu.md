使用用户本次指定或当前会话已确认的飞书商品上架管理 Base，并先核对表和字段。没有目标 Base 时，先获取用户提供的 Base 链接；仅在用户要求新建时进入建表流程。优先使用已连接的飞书工具或已配置的 `lark-cli`，按当前工具用法操作。权限不足时报告缺少的权限及受影响的表。

## 从哪里开始

- 维护一款商品时，用「商品货号」定位「商品档案」。一行一款，更新前检查是否已有同货号记录。
- 维护一条发布任务时，从「上架链接」按链接编号定位。一个链接只关联一款商品，同款可以有多条链接。只给货号时，列出对应链接；目标不明确时补问店铺、类目或发布标题。
- 看进度从「天猫上架运营总览」进入。排查候选时读「上架链接 → 待发布」，查提交结果时读「提交后待跟进」，查异常时读「上架失败 → 未解决」。读完所有候选页，验收草稿只用于验证。

## 各表写什么

仅查看或维护数据时使用本文件；看板任务另读[看板规则](dashboard.md)，无需在发布时预读。

| 表 | 写入和维护规则 |
|---|---|
| 商品档案 | 内部货号、品牌、款式、面料成分等商品事实。一款只维护一个「统一售价（元）」，供所有链接、颜色和尺码使用。 |
| SKU | 关联商品，保存基础颜色、规格、SKU 编码、库存等。发布时统一售价以商品档案为准。 |
| 尺码表 | 关联商品，记录每个尺码的原始量值和单位，例如身高和围度为厘米、体重为斤。填平台表单时再按目标单位换算。 |
| 上架链接 | 关联商品，保存平台、店铺、类目、发布标题、运费承担方式、运费模板、发货时间、发货地、发布方式、商品 ID、查重结果、提交结果和发布状态。 |
| 链接 SKU | 关联上架链接和基础 SKU，保存该链接选用的规格、平台尺码、投放库存、库存来源和 SKU 上市年月。历史链接售价只供追溯。 |
| 商品素材 | 关联商品，保留工厂原图和运营成品图，记录来源、类型、顺序和附件。 |
| 链接素材 | 关联上架链接和商品素材，记录目标槽位、顺序、平台素材标识和绑定状态。成品图可被多条链接选用。 |
| 上架失败 | 关联具体上架链接，记录失败阶段、字段或素材、原始报错、错误码、处理状态及下一步。确认问题修复后关闭并保留原始报错。 |

## 读写与核对

批量写入按总控分配的范围串行执行；发布批次用[状态接口](state-api.md)，纯资料维护保存逐条写入与读回清单。身份权限、旧读或参数问题出现后再读[恢复排查](recovery.md)。

### 链接配置

- 运费承担方式用单选「卖家承担运费／买家承担运费」；发货时间用单选「48小时／大于48小时／固定发货时间」，后两项所需的具体天数或日期另存明确值。发货地保存用户指定或平台已确认的地区，不能把某次截图的地区、时效或售价当作所有商品的默认值。
- 运费模板只保存真实店铺模板。用户要求任选时，从实际可用模板中选择；尚未取得清单时留空并说明，不能编造占位模板。卖家承担运费时，不因模板为空就判定缺资料，是否必填由当前平台表单决定。
- 同步模板供选择时，先核对店铺及完整清单，再用单选或关联模板表实现；有模板 ID 时保留名称与 ID 对应关系。转换已有字段前保留原值，核对失效选项；不要把「卖家承担运费」当作模板名称。
- 每链接独立库存写入各自「链接 SKU」的投放库存及库存来源；共享库存不能自动复制成每链接独立库存。「每规格1件」与「整条链接总计1件」须按上下文区分。已有明确配置和授权时直接执行，不重复确认。
- 批量创建链接时，按发布标题和链接编号查重，跳过重名后继续编号直到满足新增数量。仅创建任务可保留缺项；要沿用某链接的配置时，按已授权范围建立链接 SKU 和链接素材关联，不能只复制链接主记录就声称可发布。重跑按链接记录 ID、基础 SKU 或素材槽位去重，已有配置更新而非重复创建。
- 发布方式单独保存「立即上架／放入仓库」等用户选择，不用它代替发布状态。补齐资料后更新已过时的缺项说明，保留提交证据和历史失败记录。

1. 从链接跟随关联读取商品、链接 SKU 和链接素材，核对基础 SKU、尺码和选用素材归属同款商品。批量读写时按记录 ID 去重，用明确关联写入，避免按同名标题误改。
2. 资料缺失时指出表、记录和字段。保存有依据的实际值；统一售价、单位、库存或上市年月不明确时保留待补状态。库存 0 是有效值。
3. 资料齐全只说明可以进入预检。要判定能否提交、批量发布或查天猫实际状态，按[天猫上架流程](tmall.md)核对目标店铺、类目必填、查重和素材槽位。仅维护飞书表格时，在本技能范围内完成读写与核对。
4. 区分提交结果与平台状态。平台返回提交成功时保留商品 ID；未确认状态时用「已提交，待核实」，千牛明确显示出售中后才写「已上架」。查空或核对失败时记录现象和时间。
5. 写入后读回确认记录、关联和字段值。批量维护时逐条报告成功、失败及缺项。

## 从关联商品补齐发布资料

链接已有「关联商品」时，直接用商品记录 ID 读取「商品档案」「SKU」「尺码表」「商品素材」。缺少「链接 SKU」或「链接素材」行时，先根据商品资料推导可用配置，再判断是否缺项。已有的有效链接配置优先。

- **规格与尺码**：未配置销售规格时，优先使用已标明的商品默认规格；没有默认子集时，使用该商品下明确可售且能映射到目标平台的基础 SKU。尺码量值从商品尺码表取。商品 SKU 有多组且用途不明，或平台规格无法映射时，只问具体冲突项。
- **素材**：优先读取该商品中用途、顺序明确的运营成品图。目标槽位能唯一确定时直接复用。多个候选方案冲突或必需槽位没有素材时，指出具体槽位。复用图片时，按当前链接重新核实绑定状态。
- **库存和链接专属字段**：按当前链接的明确配置或已知共享库存规则取数。记录投放库存时，先确认它是共享库存展示还是独立配额，避免把同一份库存重复分配给多条链接。其他链接的库存、选图方案、运费和发布方式只有被明确指定为模板或默认值时才继承。

只做预检时可在读取结果中解析这些关联。用户要求补齐资料或提交时，把可确定的关联按当前链接补建，按链接与基础 SKU、链接与素材槽位去重，读回确认。批量中同款共用的问题只问一次，同时列出受影响的链接。
